# kakera-book

## 目的

本を読んだだけで終わらせない。本のメッセージを自分の状況に接続して、行動・判断に落とせる気付きとして kakera に残す。

元ネタは『チーズはどこに消えた』を題材にした 6 ステップ対話パターン (book-to-claude-memory 由来) を一般化したもの。

## 基本原則

- **1 セッション = 1 気付き** (発散を防ぐ)
- 5-15 分でサクッと終える
- 完璧を求めず先に進む
- 複数の本をまとめて処理しない
- 気付きは「ユーザーの言葉のまま」保存する (Claude が AI 寄りに整形しない)

## 実行手順

### 0. 書名確定

- `$ARGUMENTS` が空 → 「どの本について話す?」と尋ねる
- ある → そのまま使う

Claude がその本を知っているか確認 (知らない場合は user に主要メッセージや章タイトルを提示してもらう)。

### 1. 壁メッセージ一覧 (起点構築)

本の主要メッセージ・章タイトル・キーフレーズを 5-10 個ほどリスト表示する。

```
> /kakera-book チーズはどこに消えた

『チーズはどこに消えた』の主要メッセージ:
- 変化は必ず起こる
- 変化を予期せよ
- 変化を見張れ
- 変化にすばやく適応せよ
- 変わろう
- 変化を楽しもう
- 変化に備えて、楽しもう。何度でも

どれが今のあなたに刺さりますか?
```

### 2. 響いた箇所 (共鳴点特定)

ユーザーが選んだメッセージを受け取る。複数なら 1 つに絞ってもらう (1 セッション 1 気付き原則)。

### 3. なぜ響いたか (自分の文脈接続)

```
そのメッセージ、なぜ今のあなたに響くんですか?
```

ユーザーが自分の言葉で語る。Claude は先回りして解釈しない、聞く側に徹する。

### 4. 今の自分 (目的言語化)

選んだ本のメタファーに合わせて問う (例: チーズはどこに消えたなら「今のあなたのチーズは何?」)。
本のメタファーが無ければ、`今あなたが追い求めているもの・目標は何?` と直接問う。

### 5. 詰まっている場面 (課題特定)

```
それを追う中で、今どこで詰まっていますか?
```

具体的な詰まり方を引き出す。「なんとなく」「いろいろ」のような曖昧な答えには、コーチモード的に「もう少し具体的に言うと?」と返す。

### 6. 古い前提 (固執の正体探索)

```
詰まりの背景に、もう手放したほうがいい古い前提・思い込みは何ですか?
```

古いチーズ (固執しているもの) を言語化させる。

### 7. 気付きの結晶化

5 ステップを経て、ユーザーの中に 1 つの気付きが浮かんでくる。それを 1-2 行に要約する。

```
ここまでの話だと、今回の気付きは「X」ですか?
```

ユーザーが OK と言うまで言い直す。

### 8. 保存

気付きの性質に応じて適切なカテゴリに保存する。

| 気付きの性質 | カテゴリ |
|---|---|
| 行動指針・働き方 | `feedback/` |
| 技術選定や設計の原則 | `design/` |
| 具体的な技術判断 | `decisions/` (日付 prefix 付き) |
| 自分の背景・価値観 | `user/` |
| プロジェクト固有の文脈 | `project/` |

frontmatter には `source` フィールドを追加して出典を残す。

```yaml
---
name: <気付きのタイトル>
description: <一行要約>
type: feedback
importance: medium
created: 2026-05-19
decay: 6months
source: "book/チーズはどこに消えた"
references:
  - 2026-05-19
---

## 気付き
<ユーザーの言葉のまま>

## 文脈
<なぜ響いたか、6 ステップ対話の要点>

## 行動への接続
<今の業務・状況にどう活かすか>
```

### 9. 関連メモへのリンク

保存したノートと関連するメモが knowledge/ にあれば、双方向 wikilink で繋ぐ。同じ著者の別ノートがあればそれも。

### 10. 終了の案内

```
1 セッション = 1 気付きが原則です。他にも話したいテーマがあれば次の session で。
```

複数の気付きを連続抽出しようとしない。

## 禁止事項

- Claude が本の解釈を先回りして提示しない (ユーザーが語る前に意味を決めない)
- 1 セッションで複数の気付きをまとめて処理しない
- 「気付き」が曖昧なまま保存しない (1-2 行に結晶化されてから保存)
- 知らない本の場合に推測で内容を語らない (ユーザーに主要メッセージを尋ねる)
