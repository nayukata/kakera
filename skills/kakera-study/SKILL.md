# kakera-study

## 目的

ユーザー自身の学習を支える対話モード。
保留した疑問 (`questions/`) を Claude が直接答えず、問いを返してユーザーに考えさせる。
背景は「流暢性の錯覚」(易しく取り出せる情報を理解と勘違いする) を破ること。

## 引数の扱い

| 入力 | 動作 |
|---|---|
| なし | `questions/` 配下を全件リスト表示。番号 / タイトル / 「ランダム」「最古」で選択 |
| 完全一致 | そのノートを即開く |
| 曖昧キーワード | 関連ノートを relevance 順で並べる。1 件なら即開く、複数なら確認 |
| 自然文 | 特徴語を抽出して曖昧検索と同じ流れ |

## 実行手順

### 1. 対象ノート確定

`$KAKERA_HOME/knowledge/questions/` を走査して `$ARGUMENTS` に従い 1 件確定する。

リスト表示時のフォーマット

```
未解決の問い (3 件)
1. RLS のポリシー無し挙動を整理したい  (1 ヶ月前に保留)
2. Recoil の atom 永続化のベストプラクティス  (3 日前)
3. pgBouncer の transaction モード解除タイミング  (1 週間前)
どれにしますか? (番号 / タイトル / 「ランダム」「最古」)
```

経過時間表記は日本語で統一する (例: `1 ヶ月前` `3 日前` `1 週間前`)。`1 month` `3 days` のような英語単位は使わない。

### 2. ノートを Read + 関連メモ調査

- 対象の問いノートを Read
- 関連しそうな `knowledge/` 配下のノート (description / wikilink で特徴語が引っかかるもの) を Read

### 3. ソクラテス式対話開始

Claude は答えを先に出さない。代わりに

```
> ## 問い
> <ノートに書かれた問い>
>
> 今ならどう考える? まず自分の言葉で書いてみて。
```

ユーザーが返答するまで待つ。

### 4. ユーザー回答の評価

ユーザーの回答に対して
- 同意できる箇所は短く認める
- 不明瞭・誤解・不足がある箇所は「ここはどう?」と追加で問う
- 過去メモに既存の答えや関連知見があれば「以前 `[[X]]` でこう判断していました」と提示し、現状と照合させる
- Claude が直接答えを書いてしまわない (誘導する)

### 5. 結論の合意

ユーザーが「これで納得した」と言うか、対話が落ち着いたら結論をまとめる。

### 6. ノート更新

対象の問いノートを以下の構造で Edit する。

```markdown
---
type: question
...
---

## 問い
(既存)

## 自分の答え
(ユーザーが対話で書いた回答を要約して記載。ユーザーの言葉のまま残すのが原則、整形はしてよい)

## 補強
(Claude のフィードバックや関連メモへのリンク)

## 結論
(対話で到達した最終的な理解)
```

### 7. 通常ノートへの昇格 (任意)

ユーザーが「これで完結した、保留終わり」と意思表示したら
- ノートの `type` を `feedback` / `design` / `decisions` 等に変更
- ファイルを `questions/` から該当カテゴリに移動
- `decay` を再設定 (内容に応じて)
- 関連メモに `[[新ノート]]` を追加してリンクを張る

ユーザーが「まだ寝かせる」と言ったら
- `decay: 1month` のまま、`references` に今日の日付を追加 (再訪したことの記録)

## 禁止事項

- ユーザーが書く前に Claude が結論を提示しない (ソクラテス式の核)
- ユーザーの回答を AI 寄りに書き換えない (本人の言葉のまま保存)
- 「整理する」「最新化する」などの**メンテ**作業はしない (それは `/kakera-review`)
- 「自分の答え」未記入のまま昇格させない

## 1 セッション = 1 気付き

- 5-15 分でサクッと終える
- 複数の問いをまとめて処理しない (発散の危険)
- 終わったら「次は別 session で」と促す
